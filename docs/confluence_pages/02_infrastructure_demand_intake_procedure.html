Scope

This procedure covers the path from a new request to a triaged demand. It applies to all four sites.

Step 1 - Classify

TypeDefinitionRoutingExample
Infrastructure demandNew or changed infrastructure that needs assessment, funding or capacityEnters this pipelineORION-REQ-017 (KAN-13)
IncidentAn existing service is broken or degradedRouted to incident management on the same day; no budget or priority decision hereORION-REQ-048 (KAN-32)
Service requestA standard catalogue item with a fixed price and procedureRouted to the service catalogueORION-REQ-043

Demands, incidents and service requests are different processes. An incident is never held back for a prioritisation decision, and a demand is never fast-tracked by calling it an incident.

The same structure is used as the description template of every Jira issue in project KAN.

Step 3 - Triage

  1. Create the Jira issue with summary ORION-REQ-NNN | title, due date, priority and labels.
  2. Assign the demand analyst of the requesting site. An issue without assignee appears in the ownership-gap filter.
  3. If a mandatory field is missing, set stage-needs-info, write the question as a comment and remind the requester after 3 and 7 working days. Close the request after 10 working days without an answer.
  4. When the information is complete, set stage-triaged. Triage should not take longer than 3 working days.
