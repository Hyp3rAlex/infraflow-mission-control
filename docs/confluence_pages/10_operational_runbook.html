All content in this space is synthetic. Orion Systems Engineering is a fictional organisation used for a portfolio demonstrator. No real company data is stored here.

Weekly refresh (Monday)

  1. Export the finance ledgers and the capacity table as of Sunday evening into data/.
  2. python -m infraflow validate - read the exception register; critical findings make the report provisional.
  3. python -m infraflow all - regenerates reports, workbook and slide deck from the same data.
  4. python -m infraflow jira pull and python -m infraflow jira reconcile --snapshot ... - every difference between Jira and the data set is listed.
  5. Publish the Weekly Portfolio Review page and send the management e-mail. Do not edit numbers by hand; correct the source and regenerate.

Rules for writing to Jira

  • Read-only by default. Writes need --apply and INFRAFLOW_ALLOW_WRITE=1.
  • Before creating an issue, search for the label orion-req-NNN. One demand, one issue. A second run creates nothing.
  • The mapping between demand ids and Jira keys is stored in data/jira_mapping.json.
  • Nothing is deleted by automation. Records KAN-1 to KAN-4 are onboarding and test records and are excluded by the label orion-demand.

When something fails

Network error or 5xxTemporary outageAutomatic retry with backoff; use the last snapshot and mark the report with its date
Jira and data set differManual change in Jira or stale exportDecide which source is right for that field (see Sources of truth), correct it, reconcile again

Escalating data errors

Each exception has an owner role and a due date in the register. Critical finance exceptions go to the Finance Controller the same day; approvals without approver and spend without approval go to the Head of Digital Infrastructure. The reporting owner does not fix source data.

Known platform limits (Jira and Confluence Free)

  • Workflow validators and approval steps are not available: the gates are process controls documented in this space and enforced in the offline model.
  • The team-managed project has five statuses; the lifecycle stage is a label.
  • Filters and dashboards are private to the site; nothing is shared publicly.
