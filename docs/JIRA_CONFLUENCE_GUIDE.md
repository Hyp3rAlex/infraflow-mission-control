# Jira and Confluence configuration guide

Issue keys are in `data/jira_mapping.json`, Confluence page ids in `data/confluence_pages.json`. This guide explains the design and the manual configuration steps.

## Jira project KAN

| Element | Configuration | Enforced by Jira? |
|---|---|---|
| Issue type | `Task` for every demand record | yes |
| Identity | Summary `ORION-REQ-NNN | title`, label `orion-req-nnn`, portfolio label `orion-demand` | convention; checked by `jira reconcile` |
| Status | Five statuses of the team-managed project: Idea, To Do, In Review, In Progress, Done | yes (any-to-any transitions) |
| Lifecycle stage | Label `stage-submitted`, `stage-needs-info`, `stage-triaged`, `stage-assessment`, `stage-ready-for-decision`, `stage-deferred`, `stage-approved`, `stage-handoff`, `stage-in-delivery`, `stage-complete`, `stage-rejected`, `stage-routed-out` | convention |
| Priority | Native priority from the score band (Highest ... Lowest) | field yes, derivation no |
| Due date | Native due date = required-by date | yes |
| Ownership | Assignee set when a demand analyst owns the record; empty = ownership gap. Role names are in the description | convention |
| Classification | Labels `site-*`, `team-*`, `cat-*`, `cc-*`, `type-incident` | convention |
| Review indicators | Labels `needs-finance-review`, `needs-security-review`, `blocked`, `owner-missing` | convention; derived from the gate results |
| Dependencies | Native issue link "Blocks" (example: KAN-9 blocks KAN-18) | yes |
| Request template | Structured description: business need, request table, blocker, gate check, options, decision, risk, acceptance and handoff | convention; generated by `jira_sync.issue_payload` |
| Decision gates | Not possible on the Free plan (no validators). Process rule in Confluence; enforced in `lifecycle.py` | **no** |

The original instructions follow for reference.


These could not be done through the connector used for the build. None of them needs a paid plan.

1. **Rename the project** (optional): Project settings > Details > Name: `InfraFlow Mission Control`. The key stays `KAN`.
2. **Rename and order the board columns**: Board > ... > Configure board > Columns. Order: Idea, To Do, In Review, In Progress, Done. Rename to `Intake`, `Assessment`, `Decision`, `Delivery`, `Closed`. Renaming a column renames the status; filters in this project use labels and status categories, so they keep working, but update `STATUS_TO_JIRA` in `src/infraflow/config.py` and re-run `jira reconcile`.
3. **Save the filters**: for each row in `docs/JQL_FILTERS.md`: Filters > View all work items > switch to JQL > paste > Save filter > use the listed name.
   Alternative: create an API token, put it in `.env`, then `INFRAFLOW_ALLOW_WRITE=1 .venv/bin/python -m infraflow jira filters --apply` (this REST path is mock-tested only).
4. **Create the dashboard** `InfraFlow | Demand Operations`: Dashboards > Create dashboard, then add gadgets:

   | Gadget | Filter | Setting |
   |---|---|---|
   | Pie chart | KAN \| Open demands | Statistic type: Status |
   | Pie chart | KAN \| Open demands | Statistic type: Priority |
   | Filter results | KAN \| Overdue open demands | Columns: key, summary, due, assignee |
   | Two-dimensional filter statistics | KAN \| Open demands | X: Status, Y: Labels (shows team-* rows) |
   | Filter results | KAN \| Blocked or deferred | |
   | Filter results | KAN \| Completed in the last 30 days | |
   | Filter results | KAN \| Management attention | |
   | Created vs resolved chart | KAN \| Open demands (or project KAN) | Last 30 days |

   Finance and capacity figures are not Jira data; they stay in the reports and on the Confluence weekly review page.
5. **Board quick filters** (optional): add `labels = blocked`, `labels = needs-finance-review`, `assignee IS EMPTY`.
6. **Screenshots**: see `evidence/README.md`.
7. **Automation** (optional, Free plan includes a limited number of rule runs per month): "When a work item is created and assignee is empty, add label owner-missing"; "Scheduled weekly: JQL `KAN | Overdue open demands`, send one summary e-mail to the project lead". ### Regenerating and republishing a page
```bash
.venv/bin/python -c "from infraflow.models import load_dataset; from infraflow.confluence_pages import write_pages; write_pages(load_dataset())"
```
The HTML in `docs/confluence_pages/` uses the dialect of the Atlassian connector (not Confluence storage format). To update a page through the connector: read the page to get its snapshot token, then update with the new body. Without a connector: open the page in the editor and rebuild it from the HTML (tables and text paste cleanly; insert the Jira lists with `/jira` and the JQL from the file).

Before creating a page, search `space = "IFMC" AND title = "<title>"` to avoid duplicates.
